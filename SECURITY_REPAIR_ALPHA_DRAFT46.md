# Current alpha vault swap authorization

The owner authorization for Pool V4 / Vault V2 swaps previously covered the pool operation without covering the optional custody transfer or requiring a pool spend. The current module signs the complete vault intent: operation, vault coin, pool coin and inner hash, expiry, and either an empty transfer or exact deed launcher / held coin / destination tuple. Strict shapes reject alternate parameters. Both the actual pool coin and its reconstructed singleton puzzle must announce the operation.

A separate VSX1 custody domain binds the vault coin and held coin as well as launcher and destination. The p2_vault optional swap form asserts its actual coin ID; old six-field custody solutions retain their existing conditions and cannot consume the new swap message. The shared vault driver, registry, enrollment and validator reconstruction select the same V2 module used by swap builders. Existing nine curry parameters remain.

Full signed controls exposed two existing execution mismatches: the secp256r1 guard's declared cost was below its measured requirement (now 1,851,862), and builder notarized payments used a hashed input list instead of Pool V4's exact coin-ID nonce. Both are corrected. Pool economics and payment destinations/amounts are unchanged.

Fresh release hashes and all 58 modules are pinned in release-manifests/alpha-draft46-puzzle-hashes.json. The three changed source/hex predecessors are preserved exactly in alpha-draft46-predecessor; historical manifests and historical integrity assertions use those predecessors. Current compile/integrity assertions still check current source and bytes.

Independent read-only candidate review found no concrete surviving bypass or regression. Local checks: 1,416 protocol tests passed, 6 skipped; namespace and all 58 source/hex drift checks passed. The new signed suite covers BLS, secp256k1 and protocol-level secp256r1; parameter substitutions, missing co-spends, extra fields, empty-transfer injection, custody aliases, stale vault input and BLS network mismatch fail. Existing real Pool V4 tests now verify signatures and consensus conditions for both directions. Fresh CAT issuance controls include explicit synthetic XCH backing. Tests do not establish chain inclusion, provider behavior or browser transaction signing.
